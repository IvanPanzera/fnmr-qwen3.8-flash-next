METHODS & PROVENANCE

A measured view of routing.

fnMR presents the experts selected during 1,800 recorded questions, with the original text, English reading translations and timing data. The experiment completed on 8 October 2026. It captures effective MoE routing weights, not neuron activations or an intelligence score.

The experiment

Expert residency1,504 layer–expert pairs on GPU; remaining experts on CPU

The synthetic corpus has 20 task families per domain with multiple variants. The balanced collection was reduced from 3,600 planned questions to 1,800. Families 4, 9, 14 and 19 (zero-based) are held out, yielding 1,435 training and 365 held-out questions. This is a split for evaluating hotlist coverage, not answer correctness.

Recorded inputs range from 74 to 1,506 tokens (mean 288.27), including the chat template. Outputs range from 7 to 384 tokens (mean 194.32). Full configuration and length statistics are in experiment.json.

Reading a map

Rows are layers and columns are routed experts. Each row contains the effective normalized weights of the selected top 10 experts. Unselected experts have zero effective weight. A token map follows the original token stream, including input chat-template tokens. Original token IDs and decoded pieces are supplied.

Question means weight tokens equally. Domain means either average those question means equally or average all tokens equally. Display filters hide cells whose weight is strictly below the threshold and leave the retained weights unchanged. Automatic filters enforce the selected excluded-mass limit in every layer of each question mean or every original token. The largest loss and its witness are displayed.

Hotlists

48 train-only rankings cover every combination of domain, phase and averaging mode. Each selects 1,504 layer–expert pairs globally; layers can receive different numbers of resident experts. The UI compares held-out router mass coverage against the original global profile. Derived hotlists were not applied during this collection. These percentages describe routing coverage; they do not establish answer accuracy or speed gains.

Timings

Aggregate prefill throughput is 133.72 tokens/s and generation throughput is 30.11 tokens/s, calculated as total tokens divided by summed phase durations. Mean response duration is 8.62 seconds. Individual questions differ substantially in length; per-question values appear in the atlas.

All timing values include router-tracing overhead. Rejected speculative inputs are excluded from accepted traces. A final diagnostic pass, when required to capture the last emitted token, is recorded separately and excluded from generation timing. This dataset is the historical instrumented collection, not a controlled comparison of old and new Nebula versions.

English reading editions

Task templates were translated into English with their original variable values and literal payloads preserved. Answer prose combines Google Translate and direct editorial translations prepared on 16 October 2026; already-English answers are retained. Code, mathematical notation and numerical literals are protected. A separate English glossary explains natural-language comments and labels in preserved code and structured data. The translations are reading aids and may contain errors; selected passages received editorial corrections. The Original selector exposes the exact recorded content, including mistakes and truncated answers. Translations were not used for inference; token maps always correspond to original text. Source and translated text hashes are recorded per question.

Lossless traces and checks

All 3,600 traces were compressed and decoded again, then compared byte for byte against the original unsigned 16-bit expert IDs and 32-bit floating-point weights. Original and packed SHA-256 values accompany each phase. The viewer checks the packed hash before displaying a trace. Numerical tests compare the JavaScript means and filter results with the original Python implementation.

Source hashes and export verification are in provenance.json; totals and per-domain timings are in summary.json. The complete downloadable repository includes original corpus and analysis routines.

FNR1 file format

Each .fnr.gz file is a gzip stream. After decompression, its first 16 bytes are four little-endian fields:

byte 0:  ASCII magic FNR1 (4 bytes)
byte 4:  token count (uint32)
byte 8:  layer count = 48 (uint32)
byte 12: top-k = 10 (uint32)

n = token_count × 48 × 10
next 2n bytes: byte-shuffled little-endian uint16 expert IDs
next 4n bytes: byte-shuffled little-endian float32 weights

Unshuffle a b-byte item:
output[item * b + byte] = input[byte * n + item]
Shape: [token, layer, selected-expert slot]

The byte shuffle improves compression without changing any value. Layer and expert indices are zero-based; the interface displays token positions starting at one. The final data tag is dataset-v1.

Interpretation

Questions are synthetic and drawn from a finite set of task families. Router patterns alone do not establish causality, unique expert specialization, general intelligence or answer correctness. “Functional neural MoE routing” is an independent visualization project and a descriptive analogy. Model weights are external to this repository.
